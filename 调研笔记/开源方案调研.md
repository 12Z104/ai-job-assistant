# 开源方案调研：简历优化 / 简历×JD 匹配 / 模拟面试 / 求职自动化

- 调研时间基准：2026-10-28（UTC+8）
- 调研方式：GitHub API（api.github.com）+ GitHub 第三方统计镜像（gstars.dev）+ 项目官方站/官方博客交叉核实；GitHub 主站对自动化抓取禁用（robots.txt），star 数与许可证以 API JSON 与镜像站快照为准，均标注来源。
- 本项目背景：粘贴简历+JD → 匹配打分 → 针对性改写 → 模拟面试 → 导出 PDF/Word 的五步闭环 Web 工具（Vite+React+TS 前端 + 后端 API + SSE 流式）。

## 一、简历解析 + JD 匹配打分类

### 1. srbhr/Resume-Matcher ⭐ 本类首选参考

- 仓库：https://github.com/srbhr/Resume-Matcher
- Star：约 28.6K（GitHub API 实测 28,808；镜像站快照 28,796 / 2026-10-21）
- 许可证：**Apache-2.0**（API license 字段确认）
- 技术栈：**Python(FastAPI) 后端 + Next.js/TypeScript 前端**，前后端分离；topics 含 nextjs / vector-search / word-embeddings / resume-parser / ats；Docker 自托管
- LLM 集成：**LiteLLM 抽象层，支持 100+ 模型 provider，含 Ollama 本地模型**（官方博客明确：FastAPI+Next.js+LiteLLM+Ollama）；云/本地 BYOK；是否 SSE 流式未查到明确说明；中文支持未查到（面向英文简历）
- 核心模块：master resume 上传解析 → JD 关键词/向量（word embeddings）匹配打分 → AI 按 JD 改写简历/求职信 → 内置 resume builder 导出 PDF
- 对本项目可借鉴点：**匹配打分管线（embedding + 关键词双通道）、FastAPI+Next.js 前后端分离、LiteLLM 一套接口接多模型（含本地 Ollama）、"master resume 按 JD 裁剪"的产品思路**与本项目五步闭环几乎同构，是第一参考样本
- 查证状态：已查证（GitHub API 元数据 + 官方站 resumematcher.fyi + 官方博客架构说明）

### 2. OmkarPathak/pyresparser（简历解析库）

- 仓库：https://github.com/OmkarPathak/pyresparser
- Star：958；许可证：**GPL-3.0**（镜像站确认）；语言：Python
- 技术栈：spaCy NER + 规则匹配，从 PDF/DOCX 抽取结构化字段；PyPI 累计下载 45 万+
- 注意：**最后提交 2023-09，已停更**；GPL-3.0 有传染性，商业闭源项目慎用
- 对本项目可借鉴点：可参考其"简历 → 结构化 JSON 字段（姓名/教育/技能/经历）"的字段设计与 NER 思路；但生产级建议用 pdf 解析（pdf-parse/PyMuPDF）+ LLM 抽取替代
- 查证状态：已查证（gstars 镜像快照 + 作者官网）

### 3. markusj87/jobsifter（小众补充）

- 仓库：https://github.com/markusj87/jobsifter
- Star：仅 6；许可证：**GPL-3.0**；语言：TypeScript / Electron 桌面应用
- 定位：扫描职位列表 → 与 CV 做 AI 匹配 → 过滤高匹配岗位；2026-03 创建后基本停更
- 对本项目可借鉴点：产品形态参考价值有限，仅说明"CV×岗位批量打分"是常见需求
- 查证状态：已查证（gstars 镜像）

## 五、简历转 PDF / 解析库补充

- 浏览器端 PDF 导出事实：OpenResume、Reactive-Resume 两个主流生成器均采用 **react-pdf（@react-pdf/renderer）在前端渲染 PDF**（见两者技术栈描述与官方站）；服务端导出方案见 Snailclimb/interview-guide 的 **iText7**（Java）；Python 生态常见 PyMuPDF/pdfminer 做解析。
- pyresparser（见第 2 条）是最知名的开源简历解析库，但已停更 + GPL-3.0，建议仅参考字段 schema。
- JSON Resume Schema（见第 6 条）是跨工具交换简历数据的事实标准，可直接采用。

## 七、给本项目的落地优先级建议

1. **匹配打分模块**：精读 srbhr/Resume-Matcher 的 matching 管线（embedding+关键词双通道），并借鉴 kestrel 的"打分 + eval 评测集"做法。
2. **简历中间层数据模型**：直接采用 JSON Resume Schema，避免自造 schema。
3. **导出 PDF**：前端用 react-pdf 参考 OpenResume/Reactive-Resume 的实时预览+导出；若要 Word 导出再另选库。
4. **模拟面试环节**：参考 DeepInterview 的"CV+JD 作为面试上下文 + LangGraph 多轮编排"，以及 interview-guide 的中文评分反馈交互。
5. **LLM 接入**：用 LiteLLM 风格的 provider 抽象（OpenAI/Claude/Gemini/本地），前后端之间用 SSE 流式输出。
6. **许可证红线**：AGPL-3.0 项目（open-resume、interview-guide、kestrel）只能参考思路不能直接拷代码进闭源产品；GPL-3.0（pyresparser、jobsifter）同理；MIT/Apache-2.0（Resume-Matcher、Reactive-Resume、resume-cli、OpenCluely）可安全借鉴。

> 来源说明：star/许可证/技术栈主要来自 GitHub API JSON（api.github.com/repos/...）与 gstars.dev 镜像快照（2026-10 下旬），辅以各项目官网/官方博客交叉验证；GitHub 主站因 robots 限制无法直接抓取，故未逐条人工打开仓库网页，但所有 license 与 star 均来自 API/镜像的结构化数据，无凭记忆填写项。
