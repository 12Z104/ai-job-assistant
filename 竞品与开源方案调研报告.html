0. 为什么先做这轮调研（方法论）

按你的方法论："很多时候你以为自己的想法很新，其实市场上已经有类似产品；也有时候，一个普通想法换个用户场景，就可能有新的切入点。"

这轮调研的用途不是推翻已锁定的定位（PRODUCT.md），而是三件事：

  1. 验证——五步闭环是不是真的没人做？哪些环节其实已经很拥挤？
  2. 找差异——如果定位成立，差异点到底是什么、能不能一句话讲清？
  3. 借力——开源社区已经解决了哪些模块（解析、打分、导出、流式），V1 不该重造。

结论是：五步闭环中单步没有一步是新的（匹配有 Jobscan、改写有 Resume Worded、面试有 Final Round/Huru/Qcard、导出人人都有），但把它们串成"投递前 30 分钟"的中文闭环 + 游客即用，目前无人占据。差异在组合与场景，不在单个功能。

1. 市场格局总览：四派分立，没人做闭环

把所有竞品按"核心环节"归类，市场清晰分成四派：

① 模板建简历派

超级简历、Kickresume、Rezi、知页、简历本、锤子、五百丁、职徒、OpenResume/Reactive-Resume（开源）

卖点：模板 + AI 生成整份简历。缺：不强制输入 JD、无结构化打分、无 AI 模拟面试。

② ATS 打分派

Jobscan、Resume Worded、Huntr、Jobright、Teal（匹配是其卖点之一）

卖点：简历×JD 关键词/语义打分 + 改写建议。缺：几乎全部不做模拟面试。

③ 面试练习派

牛客 NowGPT、Final Round AI、Huru、Qcard、牛面、面灵、Google Warmup、Yoodli、InterviewBuddy

卖点：AI 面试官出题/追问/打分。缺：不做匹配打分、不做改写高亮、不强调导出。

④ 自动投递派

Sonara、LazyApply、Simplify（填表）、Jobright（延伸）

卖点：替你投递/填表。属于流程下游，与"投递前准备"闭环几乎不重叠。

还有一类：招聘平台内嵌 AI（BOSS 直聘、智联职悟空、猎聘 Dora、应届生网）——功能最全且免费，但全部绑定账号体系与真实岗位生态，是"平台的附庸功能"，不是独立工具。

2. 国内竞品（13 项，已逐个查证）

2.1 关键发现

  1. "简历×JD 结构化打分 + 改写前后高亮"没有国内产品做成独立主线：超级简历/锤子/职徒/知页的 AI 都是"生成整份 + 通用诊断"，不要求用户粘贴具体 JD；BOSS/智联/猎聘虽做匹配，但匹配结果是"岗位推荐"而非"针对这一份 JD 给简历打分并定向改写"。
  2. 模拟面试在国内已拥挤：牛客 NowGPT（技术岗最强）、BOSS AI 模拟面试、智联职悟空、猎聘 Doris、应届生无忧智面都已上线，且多免费/低价。第④步必须靠"技术实习场景 + 与改写的简历/JD 联动 + 点评质量"差异化。
  3. 游客模式 + 本地多份简历存储，所有国内产品都没有——它们全部强绑账号和招聘生态。
  4. 名单修正：妙手简历未查到活跃官网（建议剔除或补域名）；知页简历已实际并入牛客网，不再算独立竞品。

4. AI 原生 / 模拟面试类（12 项，重点对标）

4.1 关键发现：市场被切成两半，没人接起来

匹配/改写/导出强的（Huntr、Jobright、Jobscan、Resume Worded、Teal）几乎都不做模拟面试；模拟面试深的（Final Round、Huru、Qcard、牛面）不做匹配打分和改写高亮、也不强调导出。把"①匹配打分 → ③改写高亮 → ④基于这份简历/JD 的多轮模拟面试+点评 → ⑤导出"接成一条中文闭环，正是空档所在。

  • Huru（免费）与 Qcard（面向应届生）是本项目第④步最直接的对标：都能粘 JD、AI 追问、逐题打分、出复盘——但无改写高亮、无导出、中文支持未见。
  • Final Round AI 面试深度最高（8 场景、自动多维度 debrief、薄弱点重练），但要桌面 App，且主打"真实面试中实时辅助"（伦理争议品类）。
  • 伦理切割：Final Round AI / Qcard / interviewbuddy.expert 都带"面试中实时辅助（live copilot / stealth）"功能。本项目定位为考前练习，应在面试叙事中明确与"作弊辅助"品类切割——这也是一个可以讲的决策点。

5.2 落地优先级建议

  1. 匹配打分模块：精读 Resume-Matcher 的 matching 管线（embedding+关键词双通道），借鉴 kestrel 的"打分+eval 评测集"做法。
  2. 简历中间层：直接采用 JSON Resume Schema（MIT），避免自造 schema，也为 V2 模板库/云同步留好边界。
  3. 导出 PDF：前端 react-pdf（参考 OpenResume/Reactive-Resume 的实时预览+导出）；Word 导出另选库。本项目已用 localStorage，无需后端渲染 PDF 的额外依赖。
  4. 模拟面试环节：参考 DeepInterview 的"CV+JD 作为面试上下文 + 多轮自适应编排"、interview-guide 的中文评分反馈交互（思路层面）。
  5. LLM 接入：LiteLLM 风格的 provider 抽象（本项目当前为 DeepSeek，SSE 流式 + [DONE] 终止已是既有契约）——抽象层让 V2 换模型不重写。
  6. 许可证红线：AGPL-3.0（open-resume、interview-guide、kestrel）与 GPL-3.0（pyresparser、jobsifter）只能参考思路、不能拷代码；MIT/Apache-2.0（Resume-Matcher、Reactive-Resume、resume-cli、OpenCluely）可安全借鉴。

6. 差异点与机会分析（针对已锁定的五步闭环定位）

6.1 真实机会（按锋利程度排序）

机会 A——"中文 + 粘贴已有简历+JD → 结构化打分 → 前后对比高亮改写"作为产品主线。
国内外都没有独立产品把这条主线做成主体验：国内模板派不强制输入 JD（超级简历/锤子/职徒），平台派做匹配但结果是岗位推荐；国外打分派（Jobscan/Resume Worded）无中文且 AutoFix 是直接改稿、没有"前后对比高亮"的可解释交互。这一条恰好就是 PRODUCT.md 五步闭环的第 ②③ 步，V1 的主线即差异化本身。

机会 B——把"匹配/改写"与"模拟面试"接成闭环（数据回流）。
市场分两拨：匹配改写强的不做面试，面试深的不管匹配。没人做"基于刚改好的这份简历 + 这个 JD 去模拟面试"——而 PRODUCT.md 的核心设计"四步互相喂数据（面试暴露的短板回流到匹配分析）"正是这个闭环的产品化。这是面试官视角最能讲出产品思考深度的点。

机会 C——游客模式 + 本地多份存储 + 无账号。
全部竞品（国内国外）都强制注册。对"面试官打开链接即演示"和"自己 12 月 dogfooding"天然契合。副作用是不积累用户数据——但这是明确红线（不做大规模用户数据），V1 合理；可在面试叙事里主动讲"这是刻意的取舍"。

机会 D——中文技术实习的"考前练习"细分场景。
牛面做中文技术面试但无闭环；Final Round 有中文界面但桌面端+live 辅助；Huru/Qcard 免费但英文且无导出。中文 + 技术实习 + 纯考前练习（与作弊辅助明确切割）是干净空档。

6.2 伪机会 / 要小心的点

  1. "模拟面试"单独拿出来不是卖点：牛客/BOSS/智联/猎聘/应届生/Huru/Qcard/牛面/Final Round 已把单环节做满。第④步必须靠"与简历/JD 联动 + 技术实习场景 + 点评质量"差异化，不能只做"又一个 AI 面试官"。
  2. 自动投递是下游，别碰：Sonara/LazyApply/Jobright 的"替你投递"与"投递前准备"闭环不重叠，且触碰红线（真实公司对接）。
  3. 不跟平台 AI 拼功能数量：BOSS 免费且全，正面对抗无意义；差异在"独立工具 + 考前闭环 + 可解释性（打分维度/改写前后对比）"，不在功能清单。

7. 换用户场景找切入点（按你的方法论推演）

"一个普通想法换个用户场景，就可能有新的切入点。"——以下 4 个视角从"人群 / 岗位 / 环节 / 时间点"四个维度各切一刀，供讨论边界时选择。

视角 ① 只做"自学转码 → 投技术实习"人群（推荐）

场景：科班生有学历+课程背书；转码者的简历问题完全不同——项目单薄、无实习经历、被 JD 硬性条件（"计算机相关专业""3 年经验"）卡住、技术基础面试一问就露。用户本人就是这个人群的典型（前端自学、目标 AI 全栈偏前端实习）。

切入点：产品主线从"通用简历优化"变成"转码者简历突围 + 技术基础面试速成"——匹配分析专门解释"你这份简历为什么被筛掉（硬条件缺什么、项目怎么包装）"，模拟面试偏向实习面试常见题（八股+项目深挖+HR 面）。

为什么可行：牛客覆盖"技术岗"但不做匹配改写；通用模板站覆盖"应届生"但不做面试。这个交集无人做。dogfooding 完美（自己就是目标用户），面试作品叙事也最强："我给自己写的工具"。

风险：人群窄——但 V1 本来就是"服务我自己+同类一小撮人"（PRODUCT.md 原话），窄不是问题，反而是聚焦。

视角 ② 只做前端 / 泛前端岗位的匹配 + 面试

场景：前端 JD 有清晰的技能关键词体系（React/Vue/TS/构建工具/工程化/性能），打分解释性比通用岗位强得多——"你缺了 Webpack、项目里没有性能优化经历"是用户能立刻行动的结论；前端面试题题库收敛（八股+项目深挖），模拟面试能做出"前端专属"的深度，而不是通用技术岗。

切入点："前端岗专用"的 JD 匹配模型 + 前端面试模拟（含项目深挖追问）。

为什么可行：牛客是通用技术岗（Java/C++/前端混在一起），没有"前端细分"的产品化体验；国外 Rezi/Jobscan 不懂中文前端生态。可进可退：V1 做前端，V2 模板库按方向扩（PRODUCT.md 已有此规划）。

视角 ③ 换环节做深：把"一个 JD → 30 分钟闭环"做成单次会话体验

场景：求职者收到一个心仪的 JD 时，缺的不是"简历模板"，是"30 分钟内完成：匹配分析 → 针对这 JD 改写 → 一轮配套模拟面试 → 导出投递版 PDF"的即时闭环。对应 PRODUCT.md 的北极星："把求职反馈周期从几周压缩到几秒钟"。

切入点：交互上以"JD 为中心"组织（一个 JD 一张卡：匹配分、改写对比、面试记录、导出按钮），国外有 targeted resume 概念（Huntr/Huru）但没有人把它打包成"单次会话即交付"的即时体验。

为什么可行：这个场景正是五步闭环的自然形态，且不需要新功能——只是交互组织方式，V1 即可实现；演示给面试官看时"30 秒出匹配分 → 改 → 面"的动线最有冲击力。

视角 ④ 投递后场景：把"面试复盘"做深（第二版候选）

场景：面完一场，把现场问题/回忆粘进来，AI 复盘：这轮暴露了什么短板、下一版简历怎么改、下次面试怎么练。这是"反馈闭环"的延伸——面试结果回到简历与准备计划。

为什么可行：与 V2 的"面试题库+历史记录"天然衔接；数据是用户自己输入的，不涉及真实公司对接（红线不冲突）。建议放在第二版：V1 聚焦投递前闭环，复盘模块可在模拟面试点评中先埋下结构（点评输出结构化，V2 复用）。

9. 面试怎么讲（60–90 秒决策叙事）

开场（一句话定位）："我做了一个面向中文技术实习求职者的投递前闭环工具：粘贴简历和 JD，AI 做结构化匹配打分、针对性改写（前后对比高亮）、基于这份简历的多轮模拟面试，最后导出 PDF/Word。"

为什么这么做（竞品调研的决策）："开工前我花了一周做竞品调研，覆盖 20+ 产品和 13 个开源项目。市场分成四类：模板站、ATS 打分、面试练习、自动投递——但没有一个把它们接成闭环，而且全部要求注册账号、以英文市场为主。所以我的差异不是功能数量，是一个 JD → 一份针对性简历 → 一轮配套模拟面试的完整回路。"

数据回流（产品思考深度）："闭环里四步互相喂数据：模拟面试暴露的短板会回流到匹配分析，改写的版本再进入匹配——这是把'求职反馈周期从几周压缩到几秒钟'的产品化。"

取舍（主动讲红线）："我刻意不做账号、社区、支付、自动投递——第一版要的是代码写完就自动运转，不需要天天维护的运营功能；游客模式让面试官打开链接就能演示。这也解释了为什么不做 live 面试辅助：那是伦理争议品类，我做的是考前练习。"

技术借鉴（体现工程判断）："打分模块参考了开源项目 Resume-Matcher（Apache-2.0）的 embedding+关键词双通道思路，简历数据模型直接采用 JSON Resume Schema，导出用 react-pdf；LLM 层做了 provider 抽象，当前接 DeepSeek、SSE 流式输出。"

备好一个数字：全民简历 API 计价（AI 优化 1 元/份、单条改写 0.2 元、PDF 生成 2 元/次）可支撑"我的单次闭环成本约 X 元"的回答——建议 V1 上线后实测记录真实成本，面试时讲"实测"而不是"估算"。
